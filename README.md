# Finance Manager

A full-stack personal finance manager focused on **privacy, security, and useful financial insights**.

Finance Manager lets users track income and expenses, manage budgets and savings goals, monitor recurring expenses, search transactions, generate reports, and export their financial data.

The project started as a Python CLI application and was later rebuilt as a full web application using **FastAPI + PostgreSQL** for the backend and **React (Vite)** for the frontend.

---

## ✨ Features

### 🔐 Authentication & Security

* Secure login using **bcrypt password hashing**
* Separate **Master PIN** for protecting financial data
* Master PIN is **never stored**
* **Argon2id** derives a deterministic encryption key from the Master PIN and account-specific salt
* Financial amounts and notes are encrypted using **Fernet symmetric encryption**
* JWT-based authentication
* Account deletion permanently removes the user's financial data
* Display currency can be changed from the application

### 💰 Money Tracking

* Add and manage income and expenses
* Predefined expense categories
* Recurring expenses with automatic daily processing
* Automatically catches up on recurring expenses missed while the application was offline
* Search transactions by:

  * Category
  * Date
  * Exact amount

### 📊 Budgets & Reports

* Create monthly budgets
* Set budgets for individual categories or overall spending
* In-app warnings when approaching or exceeding a budget
* 90-day running balance
* 30-day daily spending trends
* 6-month income vs. expense comparison
* Monthly and yearly financial breakdowns
* Category-based charts and visualizations

### 🎯 Savings Goals

* Create savings goals
* Track progress toward each goal
* Monitor saved amount versus target amount

### 📁 Data Management

* Export financial data to **CSV**
* Generate financial reports as **PDF**
* Import transactions from CSV
* Imported CSV files follow the same format generated by the export system

## 🛡️ Security Model

Finance Manager separates **authentication** from **financial-data encryption**.

Your login password is used only to authenticate your account. It is hashed using **bcrypt** and is not used to encrypt financial data.

The financial data is protected by a separate **Master PIN**.

### Key derivation

The Master PIN is never stored in the database.

During registration:

1. A cryptographically random salt is generated for the user.
2. The salt is stored with the account.
3. The Master PIN and salt are processed using **Argon2id**.
4. Argon2id derives a 32-byte encryption key.
5. The derived key is converted into a Fernet-compatible key.

When the user unlocks their account, the same process deterministically derives the same encryption key.

### Data encryption

Financial amounts and notes are encrypted with the derived Fernet key **before being written to PostgreSQL**.

Conceptually:

```text
Master PIN
     │
     ▼
 Argon2id
     │
     ▼
Derived encryption key
     │
     ▼
   Fernet
     │
     ▼
Encrypted financial data
     │
     ▼
 PostgreSQL
```

The database therefore stores encrypted financial values rather than plaintext amounts and notes.

### JWT authentication

The application uses JWTs for authenticated API requests.

Because the application does not maintain a traditional server-side session store, the authenticated request carries the information required by the backend to access the user's unlocked financial vault.

This also means that **possession of a valid authentication token is highly sensitive**. Tokens should therefore be short-lived and the application should always be served over **HTTPS in production**.

> **Important:** This security model is designed as a portfolio/learning project and should not be treated as a replacement for a professionally audited financial-security system.

## 🚀 Getting Started

### Prerequisites

Make sure you have the following installed:

* **Python 3.11+**
* **Node.js 18+**
* **PostgreSQL**
* Git

---

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd finance-webapp
```

---

### 2. Set up the backend

```bash
cd backend

python -m venv venv
```

Activate the virtual environment.

**Windows:**

```bash
venv\Scripts\activate
```

**macOS / Linux:**

```bash
source venv/bin/activate
```

Install the dependencies:

```bash
pip install -r requirements.txt
```

---

### 3. Configure environment variables

Create a `.env` file from the example:

```bash
cp .env.example .env
```

On Windows, you can also simply copy `.env.example` to `.env` manually.

Update the `.env` file with your PostgreSQL credentials.

Generate a secure JWT secret:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Then place the generated value in:

```env
JWT_SECRET_KEY=your-generated-secret
```

### Example environment configuration

```env
DB_USER=postgres
DB_PASSWORD=your-postgres-password
DB_HOST=localhost
DB_PORT=5432
DB_NAME=finance_manager
JWT_SECRET_KEY=your-generated-secret
```

> Never commit your real `.env` file or any production secrets to Git.

---

### 4. Create the PostgreSQL database

Create an empty PostgreSQL database matching `DB_NAME`.

For example:

```sql
CREATE DATABASE finance_manager;
```

The application creates its database tables automatically when the backend starts.

---

### 5. Start the backend

From the `backend` directory:

```bash
uvicorn main:app --reload
```

The API will be available at:

```text
http://127.0.0.1:8000
```

FastAPI's interactive API documentation is available at:

```text
http://127.0.0.1:8000/docs
```

You can use the Swagger UI to test the API, including the registration endpoint.

---

### 6. Start the frontend

Open another terminal:

```bash
cd frontend
npm install
npm run dev
```

The frontend will normally be available at:

```text
http://localhost:5173
```

The frontend communicates with the FastAPI backend through the API configuration in:

```text
frontend/src/api.js
```

Only `.env.example` containing placeholder values should be committed.

## 🧪 Current Limitations

Finance Manager is still a learning/portfolio project. Some production-level features are intentionally missing.

### Database

* No database migration system yet
* Schema changes currently require recreating the database
* **Alembic** is planned for future migrations

### Performance

* Transaction lists currently load without pagination
* Large datasets may require optimized queries and pagination in the future

### Frontend

* Dashboard is currently desktop-first
* Sidebar and dashboard layouts need additional responsive work for smaller screens

### Authentication

* No password-reset flow yet
* Token/session architecture can be further hardened for production use

### Deployment

* Currently designed primarily for local development
* Production deployment, HTTPS configuration, secret management, and infrastructure setup are future improvements
